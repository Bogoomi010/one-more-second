# 프로젝트 개선 제안 커맨드

당신은 시니어 스태프 엔지니어이자 제품 관점까지 고려하는 아키텍트입니다.

현재 프로젝트 환경 제약 조건:

1. Firebase 무료 플랜(Spark)을 사용 중이다.
   - 추후 사용자가 많아지면 유료 플랜(Blaze)로 전환 예정
   - 현재는 무료 한도 내에서 운영 중

2. 프론트엔드는 Vercel에 배포되어 있다.
   - 백엔드 서버는 별도 상시 운영하지 않음
   - Firebase 기반 BaaS 구조로 추정

이 제약 조건을 반드시 고려하여 분석하고 제안하라.

---

목표:
- 코드베이스 전체를 폭넓게 검토한다.
- 어떤 기능이 추가되면 좋을지 제안한다.
- 어떤 부분이 수정되면 좋을지 제안한다.
- 제안이 프로젝트에 미칠 영향을 분석한다.
- Firebase 무료 플랜 한도 및 Vercel 환경 제약을 고려한다.
- 사이드 이펙트 가능성을 검토하고 대응 방안을 제시한다.
- 루트 경로에 "recommended dev.md" 파일을 생성하거나 덮어쓴다.

---

추가 분석 관점 (반드시 포함):

### 🔥 Firebase 관련
- 무료 플랜 한도 초과 가능성
- 읽기/쓰기 과다 구조 여부
- 보안 규칙(Security Rules) 취약점
- Cloud Functions 필요성 여부
- 트래픽 증가 시 비용 폭증 위험
- 인덱스 최적화 필요 여부

### 🚀 Vercel 관련
- 서버리스 호출 구조 적절성
- SSR/ISR 전략 적절성
- 환경 변수 및 보안 노출 위험
- API 라우트 과사용 여부
- 클라이언트에서 Firebase 직접 호출 시 문제점

### 📈 확장성 관점
- 사용자 증가 시 병목 예상 지점
- 데이터 구조 재설계 필요성
- 캐싱 전략 필요 여부
- 로그/모니터링 부재 여부

---

작업 단계:

1) 레포지토리 전체 분석
- 프로젝트 핵심 기능 요약
- 현재 아키텍처 구조
- Firebase 사용 방식
- 배포 구조 요약
- 검토한 주요 파일/디렉토리 경로 명시

2) 기능 추가 및 개선 제안 (3~7개)
각 제안은 반드시 다음을 포함:

- 제안 제목
- 무엇을 추가/수정할 것인가
- 왜 필요한가
- Firebase 무료 플랜에 미칠 영향
- Vercel 환경에 미칠 영향
- 영향 받는 파일/모듈
- 예상 작업 규모 (S/M/L)
- 위험도 (낮음/중간/높음)
- 프로젝트 구조에 미칠 영향
- 예상되는 사이드 이펙트
- 사이드 이펙트 대응 방안
- 점진적 적용 전략
- 검증 방법

3) 결과 문서 작성

루트 경로에 "recommended dev.md" 파일을 생성하고 아래 구조로 작성한다.
